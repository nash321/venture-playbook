# 首次介绍与一步一问引导

## 通用入口：先检查，再明确询问

所有宿主均执行，包括 WorkBuddy、Windows/macOS 本地宿主和云端 Linux 环境；操作系统不决定是否询问。六类脚本支持宿主使用 onboarding.py；其余宿主使用平台原生连接入口和可用的用户级状态，不调用不支持的 --harness，也不能直接跳到研究。

已有明确跳过记录时尊重选择，不自动连接、不重复询问；正在开通或授权时保留当前步骤。其余情况先检查当前宿主已经提供的生财连接，用一个真实只读工具验证。成功就告知“生财资料已连接，可以直接使用”，复用而不重复登录；读取不可用时明确询问下方问题，不把配置存在当成已连接。

是否现在连接生财资料（生财 MCP）？
- 已有会员，登录连接。
- 领取会员体验卡。
- 暂不连接，直接分析。

等待明确答复。未回复、只发项目材料、没有状态脚本都不等于跳过；保持待选择，不自动开始研究。已提供的材料保留，不要求重发。脚本记录跳过须用 `choose --choice skip --confirmed`；该标记是Agent对已收到明确选择的声明，不是脚本自行验证用户意愿。

旧版已保存的选择继续保留；无法区分旧版skip来自明确选择还是自动跳过，不自动清空旧记录，用户主动要求连接时再恢复。平台不能持久保存时只说明实际限制，本次对话记住选择，不宣称连接一定不能跨对话保留。

## 首次介绍，只在需要选择时出现

想找适合自己的副业或创业项目，可以先看看生财有术的项目案例和创业复盘，了解别人如何获客、交付和变现，再让AI帮你拆解方法。

还没有加入生财有术？用微信扫描下方海报二维码，添加生财客服微信，向客服申请开通**3天体验卡**。等客服明确确认已开通后，再回到AI继续连接。

**直接用：**给 AI 文章、链接或项目想法，它就能帮你分析项目、生成报告和行动清单。

**加入后更强：**连接生财资料，让 AI 从精华帖、风向标等文章中，找更多相关案例、拆解实战方法，整理下一步怎么做。

暂时不想加入也没关系，直接开始分析你的项目，AI仍会搜索全网相关资料作为参考。

**在宿主中直接展示原图：**运行 `onboarding.py status` 得到绝对 `poster_path`，使用宿主支持的图片附件或 `![会员体验卡海报](<绝对图片路径>)`。图片位于本Skill根目录 `会员体验卡海报.jpg`，不要复制开发者电脑路径。终端不支持内嵌图片时使用实际图片预览/打开功能；说明界面限制，不能把只打印文件名当作已显示图卡。

选择：**已有会员，登录连接 / 领取会员体验卡 / 暂不连接，直接分析**。

固定分享入口来自原图二维码：`https://work.weixin.qq.com/ct/wcde937479180800d2ce8d79af05f9644fde`。二维码来源保持固定，不替换为其他分享链接。引导客户扫码添加客服、申请开通3天体验；HTML不设置企业微信领取按钮，点击海报仅放大查看。

## 客服确认开通后，回到AI继续

扫码连接的是生财客服微信。客户联系该客服申请开通3天体验卡；**扫码、添加客服、发出申请、已注册都不等于已开通**。不由Agent替客户发送客服消息或确认开通。

客服明确确认已开通后，客户回到刚才使用本Skill的AI对话，发送 **“体验已开通，连接生财有术”**。HTML提供“复制这句话”；复制只写剪贴板，不确认开通、不登录、不授权。

客户明确回复“客服已确认开通”“体验已开通”“体验已开通，连接生财有术”时，Agent才调用 `onboarding.py activated --confirmed`，再检查当前连接；需要时进入原生OAuth。该标记只记录客户报告，不认证客服开通状态或OAuth成功。

仅说“已加客服”“已联系”“已注册”时，不调用activated。当前体验申请处于pending时，仅说“连接生财有术”或“继续引导”仍停在等待开通；不能触发登录命令。等待过程中基础分析继续可用。

已有生财会员主动连接时，先检查现有连接，能读就复用，不重复扫码申请体验；没有连接且当前对话不清楚是已入会会员还是申请中的客户，只确认账号已可用/客服已开通这一项，再准备OAuth，不自行推定已经开通。

## Agent脚本用法

命令只由Agent后台执行，不给客户展示。选择register表示领取体验流程，内部兼容旧choice；旧register阶段按联系客户服务承接。

```sh
python <Skill>/scripts/onboarding.py choose --harness <宿主> --choice register
python <Skill>/scripts/onboarding.py step --harness <宿主>
python <Skill>/scripts/onboarding.py advance --harness <宿主>
# 只有客户明确表示客服已确认开通，才执行：
python <Skill>/scripts/onboarding.py activated --harness <宿主> --confirmed
```

`step`只返回当前一步。`trial_activation=pending`期间，choose connect/check保持等待，advance不能跨过await_activation，login/verified拒绝执行；跳过后恢复也保留等待。客户确认开通后activated只进入verify，认证仍为unknown。

已有会员使用 `choose connect`，先做真实只读检查；无可读连接才进入login。`agent_action`为当前宿主的原生登录参数数组，复用实际连接名，不拼接shell字符串；保留进行中的登录进程，不能重复启动OAuth。OpenCode按兼容说明启用已配置连接。

首次介绍未答复保持待选择，不记录skip、不自动进入基础分析；已开始的开通等待/登录/授权保持当前步骤，不能把无回复当成开通、完成或跳过。主动“继续引导”用resume；“已登录/已授权”按实际当前页面继续对应步骤。

## 体验路径

`scan（扫码加客服）→ contact_service（申请开通）→ await_activation（等待客服确认）→ activated --confirmed → verify → 需要时login → sign_in → authorize → verify → done`

收到“已加客服”后只让客户联系该客服申请开通；收到“已联系”后只让其等待客服确认。收到明确开通确认后再回AI连接。客服开通、客户报告开通、OAuth授权和实际读取是不同事实，分别记录。

## 登录路径

- WorkBuddy、ChatGPT网页及其他平台：使用当前平台实际提供的官方 MCP/连接器入口，每次只引导一个用户动作；不能套用其他宿主的登录命令。入口不明时核对该平台官方说明。缺少入口或权限则说明具体阻塞并提供“暂不连接”的选择，不自动替用户选择。

- Codex：后台原生 `codex mcp login <已配置连接名>`，客户只确认页面打开；下一轮登录本人账号，再下一轮确认授权。
- Claude Code：当前版本支持 `claude mcp login <已配置连接名>`；使用前核对当前客户端帮助。旧版不支持时只给当前 `/mcp` 面板的一步，不猜命令。
- OpenCode：客户选择连接后启用已预配置连接，后台 `opencode mcp auth <连接名>`；逐步完成页面登录与授权。
- Cursor、Windsurf/Devin：先让客户打开MCP面板找到生财连接，确认找到后再给点击认证这一步；然后逐步登录和授权。必要的宿主信任由客户亲自确认，不伪造信任记录。
- Gemini CLI：其认证入口是交互式 `/mcp auth <连接名>`，名称以有效安装回执为准。先打开入口，再逐步完成浏览器登录和授权；有能力操作当前客户端界面时由Agent准备入口。

配置由脚本默认后台完成，登录选择与实际授权独立。OAuth由宿主安全管理，不能索要或回显口令、验证码、Token、授权code、Cookie或完整回调地址。不要复制教程中的“清授权缓存”“开放全部权限”来扩大权限；遇到实际阻塞只处理本次必要项。

## 成功检查与失败分支

授权完成后，实际调用 `searchTopic / topicDetail / projectLibList / listMenu` 中一个只读工具。工具必须属于当前宿主实际已连接的生财服务，结果确实成功；不额外检索客户私人历史。生成不含正文/身份/凭据的本地检查回执：`ok=true, server_url, operation=read, tool, verified_at`，再交给 `onboarding.py verified --receipt <回执路径>`。

当前宿主已暴露有效的生财连接时，先用 `onboarding.py check` 进入只读检查，复用该连接，不执行登录命令。`check` 本身只改变引导阶段，不声称认证成功。客户选择跳过时即使留有有效OAuth也按全网模式处理。

`status` 返回历史核验记录和当前待检查状态，不能据历史记录认定本会话可读；只以本会话真实调用和 `verified` 当次返回作为可读依据。宿主云端连接与新配置的原生连接分别记录，不能互相冒称已登录。

该回执记录Agent刚取得的真实工具结果；脚本校验回执字段，**不自行向服务器验证**。模拟回执只能验证本地状态处理，不能证明OAuth完成或资料可读。

- 配置成功但本会话未加载：只引导新开/重启当前宿主会话这一项，保留原配置与授权，不重复安装。
- 账号未开放某内容：说明实际权限范围，用用户提供的有权材料或全网资料继续，不催促购买。
- OAuth或网络失败：保留当前步骤，给一个可执行的恢复动作；客户跳过就持久化并继续全网分析。
- 客户下次主动提起才恢复；不重新展示营销海报，不把“配置已存在”或“客户说已完成”写成已授权。
